# Engineering & Game Modding Rules

## Engineering Discipline
- **Task Workspace & Directory Confinement:** All file reads, creations, modifications (`edit_file`, `write_file`), and terminal commands (`run_command`) must remain strictly confined within the specific target project directory relating to the active task (e.g. `/home/ericparsley/Documents/GitHub/<repo>/`). Never create scratch files, temporary outputs, or build artifacts in parent directories (`/home/ericparsley`), `~/.gemini/`, Desktop, or unrelated sibling repositories unless explicitly requested.
- **Plan Before Major Modifications:** When working on complex tasks, multi-file refactors, or new mod architectures, outline the implementation plan or invoke `writing-plans` / `/plan`.
- **Systematic Debugging:** Trace bugs and game crashes to root causes via engine logs, stack traces, and reproducible test cases before changing code. Do not speculate or randomly alter values.
- **Evidence-Based Completion:** Verify that code builds, unit tests pass, and assets parse before declaring any task complete.

## Game Modding & S.T.A.L.K.E.R. EE Rules
- **Protect Vanilla Baselines:** Treat unpacked game archives (e.g. `unpacked/`) as strictly read-only references for diffs. Mod files belong in project mod source directories.
- **LTX Syntax Discipline:** Respect case-sensitivity, correct section headers (`[section]`), inheritance (`[child]:parent`), and avoid trailing commas or malformed keys.
- **Audio Integrity:** When modifying or converting S.T.A.L.K.E.R. audio, never use standard editors that strip the proprietary GSC binary engine chunk from the Ogg Vorbis comment header. Use ZoneForge asset replacement tools to preserve distance and volume parameters.
- **Autonomous Hands-Free Playtest & QA:** When testing ported mods (e.g. S.T.A.L.K.E.R. Complete to OGSR) without live user input, immediately launch `stalker-playtest-runner` (interoperating with `self-improving-qa`, `nav-graph-recorder`, and `game-window-helper`) to autonomously dismiss 'Press any key to play' loading screens, inject god mode / infinite ammo cheats, take control of character movement via `/dev/uinput`, monitor frames for missing textures/freezes, and auto-triage crash dialogs.
- **X-Ray Crash Interception & Modal Dismissal:** When OGSR or X-Ray crashes under Wine/Proton and spawns a Notepad or BugTrap crash log window (`xray_*.log - Notepad`), immediately run `xray_crash_handler.py sweep` or rely on `stalker-playtest-runner` to extract the crash stack trace and terminate `notepad.exe` so tests never hang.
- **Dialogue & Conversation UI Integrity:** When editing string tables or conversation scripts, validate XML syntax, missing string IDs, text overflow, and talk dialog formatting with `game-dialogue-tool` to prevent runtime truncation or CTDs.
- **Weather, Lighting & Telemetry Tuning:** Balance sun shafts, bloom, and dynamic skyboxes using `weather-lighting-tuner`, and monitor live rendering metrics using `mangohud-configurator`.
- **Task Velocity & Anti-Thrashing Discipline:** Enforce `task-velocity-governor` (5-step targeted rule, stop once tests pass, break 3-strike file churn loops) and `first-principles-reasoning` (Chain-of-Verification, Ockham's razor on bug hypotheses) to ensure porting tasks don't take longer than necessary.
- **Laptop Acoustics & Night Governance:** Interoperate with `laptop-performance-profile` (use `laptop_performance_controller.py sleep-mode` during overnight runs or when muted, and `boost-exec` for heavy parallel builds).
- **Lore Research & Web Architecture:** When documenting game lore, faction histories, or creating modding web portals, leverage `humanities-lore-research`, `creative-web-design-archetypes`, `static-site-architecture`, and `interactive-data-visualization-web`.

## Output Token Economy & High-Density Visibility
- **Zero Conversational Fluff:** Omit pleasantries, preambles ("Sure, I can help with that", "Now I will proceed to..."), and conversational sign-offs. Lead directly with the technical result or action.
- **High-Density Status:** Report multi-step progress using compact checklists (`[✓] Step complete`, `[→] In progress`) rather than multi-sentence narratives.
- **Silent Tool Success:** Do not narrate routine tool executions or echo entire successful command outputs into chat. Show only actionable errors, test pass/fail tallies, and critical metrics.
- **Surgical Edits Over Rewrites:** Always prefer targeted chunk replacements (`replace_file_content`) over full-file overwrites to minimize token thrashing.
- **Artifact & File Offloading:** For extensive plans, large reports, detailed logs, HTML templates, reactive micro-apps, landing pages, contracts, proposals, and invoices, write them directly to files or artifacts and provide a clickable link with a 1-line headline, rather than dumping large blocks of text, HTML, or markdown directly into the chat transcript.
- **Zero Code & Template Duplication in Chat:** Once code, HTML templates, or documents are created or modified via tools, never re-paste the content blocks into chat. State only the file link, line range, and rationale.
- **Zero Prompt Restatement:** Never echo or paraphrase the user's request. Lead immediately with the action, data, or checklist.
- **Token Economy Visibility:** Conclude plans, refactors, and multi-step workflows with a single high-density token savings line: `📉 Token Economy: ~<N> tokens saved (<breakdown, e.g. surgical diffs, artifact offload, Flash routing>)`.

## Hardware-Aware High-Performance Execution & Local CPU/GPU/RAM Quota Offloading
- **Dynamic Thread Saturation (32 Threads):** Automatically saturate all available CPU threads when compiling, running test suites, or batch-processing textures/audio (`-j$(nproc)` / `MAKEFLAGS="-j$(nproc)"`, `CARGO_BUILD_JOBS=$(nproc)`, `CMAKE_BUILD_PARALLEL_LEVEL=$(nproc)`, `ProcessPoolExecutor(max_workers=os.cpu_count())` via `cuda-numpy-batch-texture-dsp-processor`). Never default to single-threaded builds or pixel loops.
- **30 GB RAM `/dev/shm` tmpfs Accelerator (`ramdisk-tmpfs-build-bake-accelerator`):** Stage intermediate Blender texture bakes, contact sheet renders, game archive extractions (`.db`/`.pak`), and CMake `TMPDIR=/dev/shm` objects in `/dev/shm` (`~40 GB/s` RAM bandwidth, zero SSD wear) and clean up on exit.
- **NVIDIA RTX 5060 OptiX & CUDA Dispatch (`rtx-optix-gpu-baker-denoiser`):** In headless Blender 5.2+ (`bpy`), always activate `compute_device_type = 'OPTIX'` (`scene.cycles.device = 'GPU'`) with AI OptiX Denoising at `16–32 samples` for sub-second baking and rendering rather than slow CPU fallback.
- **Zero-Quota Local Offload Pipeline:** Automatically offload symbol scanning (`local-ast-compiler`), codebase semantic search (`local-rag`), line-slice extraction (`slice-reader`), stdout truncation (`token-guard`), local HUD/dialog OCR & image downscaling (`local-gpu-vision-ocr-preprocessor`), 3D/matrix/physics/symbolic math (`game-math-solver` on 32-thread CPU + RTX 5060 CUDA 13.4), and boilerplate/log summarization (`local-coprocessor`) to host CPU/GPU/RAM before spending cloud tokens. Never burn cloud CoT thinking tokens doing manual matrix multiplication, coordinate basis conversions, ODE parameter scaling, or algebraic derivations in-head.
- **Automatic Closed-Loop Skill Self-Evolution (`self-evolving-skill-synthesizer`):** Across **all** installed skills, whenever you fix a stale instruction/API workaround, research a verified domain table/blueprint online (`autonomous-3d-reference-researcher`), or author a reusable verified helper script (`> 25` lines), automatically persist it mid-task via `skill-evolve --hot-patch <skill>`, `skill-evolve --append-rule`, or `skill-evolve --promote <script> --to <skill>` so every skill continuously self-improves.
- **2D Drawing-to-3D Silhouette Lock (`concept-art-sketch-to-3d-sculptor`):** When creating 3D models from 2D drawings/refsheets, automatically extract mathematical contour slices (`silhouette_iou_profiler.py profile`), research real-world anatomical/mechanical ratios online, fuse primitives with SDF voxel remeshing (`blender-sdf-organic-remeshing`), and verify `Silhouette IoU >= 0.80` against the reference image.

## Quota Governance & Uninterrupted Execution
- **Never Quit on Available Quota:** Quota percentages (e.g. 5h: 86%, Wk: 96%) indicate healthy available headroom. Never quit, halt, or abort autonomous goals or test runners when quota is available (> safe reserve limits).
- **5-Hour Exhaustion Wait-for-Refresh:** If rolling 5-hour quota reaches or drops below safe reserve during autonomous runs, do not abort or fail the task. Stage working state to `.agents/memory/activeContext.md`, safely sleep until the recorded reset timestamp passes, verify quota replenishment, and seamlessly resume execution.
- **50% Weekly Quota Safe Mode (Local Fleet Diversion):** When weekly quota drops to $\le 50\%$, automatically divert code generation, C++ refactoring, LTX configs, and planning to the local model fleet (`local-coprocessor`, `agy-omni-mode --exec`, `qwen2.5:72b-iq2`, `deepseek-r1:70b-iq2`, `phi3.5:latest`, `deepseek-r1:1.5b`) to preserve the remaining 50% cloud reserve safely until the weekly reset.
- **Smart Checkpoint at 25% Weekly Reserve:** When weekly quota nears 25% remaining, automatically snapshot all uncommitted diffs, git branch, and active hypothesis context to `.agents/checkpoints/` and update `.agents/memory/activeContext.md` before continuing execution.
- **Automatic Repository Sync & Milestone Pushing (`autonomous-git-repo-sync-governor`):** When starting work on a repository, run `repo-auto-sync --pull <repo>` to incorporate upstream changes. During long sessions or general multi-step tasks, automatically commit and push verified milestones via `repo-auto-sync <repo> --checkpoint -m "<type>(<scope>): <summary>" --push` (which automatically blocks `>50 MB` binaries and temp files) so work is continuously persisted to GitHub.
- **Uninterrupted Compaction & Seamless Goal Resumption:** Compaction must **never** interrupt an active goal, plan, or test run. Always execute compaction at clean step boundaries (immediately after a tool or test run completes, before the next edit cycle). Before `/compact`, verify `.agents/memory/activeContext.md` contains the active goal, current in-flight state, and resumption instructions. Upon resuming post-compaction, immediately read `activeContext.md` (<300 tokens) and proceed directly to the next step without pausing or asking the user for direction.

## Gemini 4 Argon Thinking Governance & Internal CoT Quota Clamping
- **Direct Tool Action Over Monologue:** When calling tools (`view_file`, `replace_file_content`, `run_command`, `write_to_file`), invoke the tool call directly without preamble, internal speculative monologues, or reciting file contents in reasoning.
- **Thinking Token Budgeting:** Restrict internal reasoning to structural problem-solving (e.g. edge cases, compiler error diagnosis, architecture). Routine file edits, syntax fixes, and bash command dispatches must execute with minimal reasoning overhead.
- **Copy-Then-Patch Over Full-File Regeneration (`gemini-copy-then-patch-edit-governor`):** When creating a new version of an existing script, shader, or source file (`foo_v4.py` $\rightarrow$ `foo_v5.py`, or any variant `> 50` lines), **never** call `write_to_file` to regenerate the entire file through the output decoder (which burns `17k–28k` output/thinking tokens). Always run `cp -f <src> <dst>` via `run_command` (`~15` tokens) followed by surgical `replace_file_content` diffs (`<= 45` lines).
- **Mandatory `StartLine`/`EndLine` Window Slicing (`gemini-ast-symbol-window-slicer`):** Never call `view_file` without `StartLine` and `EndLine` on files `> 100` lines (which dumps 800 lines into context). Locate line numbers first with `grep -n` or `local-ast-compiler`, then read `<= 80`-line windows.
- **Implicit KV-Cache TTL Protection (`gemini-implicit-kv-cache-ttl-keeper`):** Pipe long playtest/build commands to `/dev/shm/<job>.log` and read `tail -n 25`. Before starting any job expected to run `> 60s`, if active context exceeds `120k` tokens, stage state to `.agents/memory/activeContext.md` and compact first so post-wait cache expiry never re-bills `160k+` uncached input tokens.
- **Hybrid "Argon Brain, Flash Hands" Protocol:** For execution-heavy tasks, prefer dispatching file editing and terminal commands via Flash (`--effort low` or `gemini-3.8-flash-low`), reserving Argon (`pro` / `--effort high`) for complex architectural analysis, difficult debugging, and plan formulation.
- **Dynamic Repo Cheat Sheet & Cross-OS Parity (`dynamic-repo-model-cheatsheet`, `windows-linux-cross-os-runtime-bridge`):** Consult `agy-cheatsheet` (`cs`) or the bottom-of-statusline `🧭 CS [...]` bar for live per-repo model/effort/hardware routing (`Argon•High+Flash`, `Argon • High`, `Argon • Med`, `Flash • Low`), and maintain native Linux + Windows 10/11 cross-OS compatibility across all scripts and skills.

## Voice Dictation & Natural-Language Slash Command Routing (`agy-mic-button`, `voice-prompt-context-optimizer`)
- **Spoken `"Set a goal..."` $\rightarrow$ Automatic `/goal` Execution (`autonomous-goal-governor`):** Whenever a user prompt begins with or contains spoken natural-language command phrases such as *"set a goal..."*, *"start a goal..."*, *"run a goal..."*, or *"goal: ..."*, immediately treat it as a full `/goal` invocation: formulate a machine-verifiable completion contract in `.agents/memory/activeContext.md` and execute autonomously end-to-end without stopping until all verification gates pass.
- **Spoken `"Make a plan..."` / `"Use boost..."` / `"Grill me..."` Routing:** Automatically map spoken *"make a plan..."* / *"set a plan..."* to `/plan` (`writing-plans`), *"use boost..."* / *"boost mode..."* to `/boost` (`first-principles-reasoning` + `argon-adversarial-verification-gate`), *"grill me..."* to `/grill-me` (`brainstorming`), and *"clamshell mode"* / *"lid closed 3D mode"* to `laptop-perf clamshell-3d`.

## Git Safety & Blast Radius Defense
- **Destructive Command Prohibition:** Never execute destructive git operations (`git reset --hard`, `git clean -fd`, `git checkout -- .`, `git push --force`, or branch deletions) without explicit, unambiguous user confirmation.
- **Atomic Staging & Binary Shield:** Never execute blind `git add -A` or `git add .` from root. Inspect `git status` first and stage only modified files relating to the active task. Strictly prevent staging large binaries (>50 MB), archives (`.zip`, `.7z`, `.pak`, `.db`), virtual environments (`.venv/`, `node_modules/`), or intermediate build outputs (`build/`, `bin/`, `obj/`, `__pycache__/`).
- **Conventional Commit Clarity:** When crafting commit messages, adhere to standard Conventional Commits format (`feat(scope): ...`, `fix(scope): ...`, `refactor(scope): ...`, `chore(scope): ...`) with a concise 1-line summary.

## Autonomous Anti-Thrashing & 3-Strike Error Recovery
- **The 3-Strike Failure Pivot:** If a compiler build, unit test, or tool call fails 2 consecutive times with the same or similar error, do NOT attempt a 3rd minor syntactic variation of the same hypothesis.
- **Systematic Pivot Protocol:** On Strike 3, immediately halt execution, step back to first principles, re-read the enclosing scope and call site via `slice-reader` or symbol search, verify foundational assumptions, or ask the user for guidance rather than burning quota in an iterative churn loop.

## Hermetic Dependency & Environment Hygiene
- **Virtual Environment First:** In Python projects, always execute via the project's local virtual environment (`.venv/bin/python`, `.venv/bin/pytest`, `.venv/bin/ruff`) rather than host system Python. Never invoke `pip install` globally or pollute `/usr/lib/python*`.
- **System Command Protection:** Never execute commands with `sudo` unless explicitly requested and approved by the user. Prefer local user binaries in `~/.local/bin/` or workspace dev dependencies.

## Secrets & Credential Shielding
- **Zero Token Leakage:** Never output, echo, log, or commit secret keys, API tokens (`GEMINI_API_KEY`, `ANTHROPIC_API_KEY`, `GITHUB_TOKEN`), private keys, or `.env` credential files to chat transcripts, artifacts, or git history.
- **Redaction Protocol:** If error logs or configuration dumps contain potential secrets, automatically mask or redact them before reporting findings.

## Codebase Docstring & Formatting Preservation
- **Documentation Integrity:** Never delete, strip, or summarize existing comments, docstrings, copyright headers, or type annotations in untouched sections of code during file edits.
- **Style & Idiom Matching:** Match existing indentation (tabs vs. spaces, 2 vs. 4 spaces), naming conventions, and file structures already established in the target codebase.

## Subagent Orchestration & Context Hygiene
- **Context Offloading via Research Subagents:** When a task requires broad codebase reconnaissance, multi-file keyword sweeps, or reading large documentation sets, invoke the `research` subagent to perform the discovery and return synthesized findings, keeping the parent conversation context lean and fast.
- **Subagent Boundary Enforcement:** Subagents must strictly inherit all directory confinement and token economy rules, never modifying files outside the active workspace.

- **Zero Conversational Mirroring for Voice Prompts (`voice-prompt-context-optimizer`):** When receiving conversational, stream-of-consciousness, or speech-to-text dictation from `agy-mic-button`, never mirror the conversational tone. Never output pleasantries, conversational preambles ("Sure, I can help with that"), or restatements. Strip conversational filler internally and lead directly with technical results or actions.
- **Phonetic & Code Term Normalization:** Transparently map spoken phonetic transcriptions into exact technical code tokens: *"see plus plus"* $\rightarrow$ `C++`, *"oh gee ess are"* $\rightarrow$ `OGSR`, *"ex ray"* $\rightarrow$ `X-Ray`, *"ell tee ex"* $\rightarrow$ `LTX`, *"dot cpp"* $\rightarrow$ `.cpp`, *"you input"* $\rightarrow$ `/dev/uinput`, *"pie test"* $\rightarrow$ `pytest`, *"cmake lists"* $\rightarrow$ `CMakeLists.txt`, *"get status/commit/push"* $\rightarrow$ `git status/commit/push`.
